### Amendment to W24 "Heartbeat Architecture Deprecated; Cron-Only is the Standard": launchd for Script Jobs

## Type
- [x] Configuration change
- [x] Scheduled task added or modified
- [x] Other: architectural decision (supersedes part of a W24 entry)

## Summary
Scheduled Mac Mini jobs that just run a repo script move from `openclaw cron` to launchd LaunchAgent plists; `openclaw cron` stays only for jobs that need Earnest's agent turn.

## Details
- Date: 2026-11-04. Decision: Steve. Logged by Manfred (Claude Code, laptop).
- This amends the W24 entry "Heartbeat Architecture Deprecated; Cron-Only is the Standard". The heartbeat deprecation in that entry still stands. Its "all recurring work runs via `openclaw cron`" rule is superseded as follows:
  - **Script-only jobs -> launchd.** Any scheduled job that runs a repo script with no agent reasoning is a launchd plist, committed at `~/autopilot/deploy/launchd/com.merritt.autopilot.<job>.plist` with `__REPO__`/`__HOME__` placeholders, `ProgramArguments` via `scripts/autopilot-env.sh` (Keychain), and an explicit PATH. Matches Steve's global CLAUDE.md "Scheduling on the Mac Mini" rules.
  - **`openclaw cron` only for agent-turn jobs.** Jobs that need Earnest to draft (gpt-5.4-mini) and send Telegram button messages stay on `openclaw cron`: today `x-monitor-fast`, `x-monitor-slow`, `rss-check`.
  - **Never system `crontab`** on the Mini.
  - **Telegram contract amendment (Bundle #3, commit `a0c0bd7`):** launchd script jobs may send plain one-way `sendMessage` notifications (no `reply_markup`, no `getUpdates`). Buttons, callbacks and inbound remain Earnest's via OpenClaw. This matches what `morning-sports-digest.R`, `x-weekly-digest.R` and `draft-expiry-nudge.R` already do.
- First job under the new rule: `com.merritt.autopilot.x-daily-note` (5:00pm ET). Runs `openclaw-scripts/x-daily-note.R`, which reads the new per-day X cache (`data/x-daily-cache/YYYY-MM-DD.jsonl`, written by `x-monitor.R` on every scan), drafts one Substack Note with `claude-opus-5-5`, writes `staging/notes/YYYY-MM-DD_daily_note.md`, and sends it to Telegram.
- Related `x-monitor.R` change: it no longer exits early once the 8/day surfacing cap is hit. It keeps scanning (cache only, no new candidates) so the daily cache covers the full day. Expect more X API reads on afternoons/evenings when the cap fills early.
- Repo docs updated in the same autopilot change: `CLAUDE.md` (scheduling section, Telegram section, Do NOT list), `README.md`, `openclaw-scripts/README.md`. Commits: autopilot `beb7fb9` (x-daily-note, plist, x-monitor cache) and `7af5878` (CLAUDE.md).

## Why
Steve's standing rule (global CLAUDE.md) is launchd-only for Mac Mini scheduling: system cron needs Full Disk Access, can't reliably reach the Keychain, and skips jobs missed during sleep. The autopilot repo still carried the W24 cron-only wording, so new work was being scheduled the wrong way. A carve-out keeps `openclaw cron` for the jobs a plist genuinely can't do (an Earnest agent turn).

## Rollback / Kill Switch
- Stop the job: `launchctl bootout gui/$(id -u)/com.merritt.autopilot.x-daily-note` and delete `~/Library/LaunchAgents/com.merritt.autopilot.x-daily-note.plist`.
- Restore the early-exit at cap in `x-monitor.R`: `git revert` the autopilot commit (also removes the cache writes).
- Policy rollback: append a new entry here; do not edit this one.

### X Reply Overhaul: Voice Sample, Prompt Rewrite, Multi-Option Drafts, Sonnet 5.5

## Type
- [x] Configuration change
- [x] Scheduled task added or modified
- [x] Model tier change
- [x] Incident or near-miss (fact-check parse bug, see Details)

## Summary
Reply drafts move from one bland gpt-5.4-mini reply to up to three options (data / needle / verdict) drafted by Claude Sonnet 5.5, voiced from Steve's real best replies, and gated by a fixed fact-check on all tiers.

## Details
- Date: 2026-11-04. Decision: Steve. Logged by Manfred before Earnest's deploy, per the pre-flight convention.
- Trigger: Steve reported the drafted replies were "bland and vanilla" and rarely used. A review of his last 89 hand-written replies against `prompts/x_reply_tier_*.md` found the prompts banned his strongest moves (sarcasm, hard verdicts, rhetorical questions, the parallel-contrast close). The voice sample was Substack explainer prose, and drafting ran on gpt-5.4-mini.
- Autopilot changes (this pull):
  - `openclaw-scripts/reply-voice-sample-refresh.R`, weekly launchd job `com.merritt.autopilot.reply-voice-sample`. Writes `data/voice-sample/reply_voice_sample.txt`.
  - All five `prompts/x_reply_tier_*.md` rewritten (old versions in `prompts/archive/2026-11-04_*`). New `{reply_voice_sample}` placeholder replaces `{voice_sample}`. Output is now `OPTION n (style):` lines or `SKIP`. `[STAT: ...]` placeholders are allowed.
  - `x-length-check.R`: ceiling 240 -> 320. New `has_placeholder` / `placeholders` fields.
  - `x-fact-check.R`: scope Tier 2 -> all tiers. Placeholders and opinions are not claims, and the tweet's own content is taken as given.
  - `x-surfacing-log.R` / `x-feedback-log.R`: new optional `options`, `option_index` and `option_style` fields.
  - `x-monitor-list.md`: @TheBuckeyeNut, @TheHoody27, @BuckeyeNatty, @11W added at tier 1B.
  - `x-engaged-accounts.md`: seeded with 12 handles. It was empty, so every candidate had been "cold".
- **Near-miss found during testing:** since the fact-check gate launched (2026-09-02), any check where Haiku used web search returned multi-block prose. Only the last block was parsed, giving "could not parse fact-check response", so the tier-2 draft was silently suppressed as `failed_skipped`. A second path (tool-less follow-up after a lookup) sometimes ended with no verdict. Both fixed: the parser joins all text blocks and extracts the verdict JSON, and the follow-up demands the verdict. On the laptop, 6/6 repeat runs returned real verdicts afterward. Earnest to size the historical impact (handoff step 4).
- Model change: the drafting step of `x-monitor-fast` / `x-monitor-slow` goes from `openai/gpt-5.4-mini` to `anthropic/claude-sonnet-5-5` (effort medium). Volume is at most 8 candidates/day, so cost is negligible. Scanning and `rss-check` are unchanged.

- Earnest's full instructions: `~/autopilot/openclaw-scripts/HANDOFF-2026-11-04-reply-overhaul.md` (pause the monitor jobs BEFORE pulling).
