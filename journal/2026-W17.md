### Secrets Migration: 1Password CLI → macOS Keychain

## Type
- [x] Credential rotation or access change
- [x] Configuration change

## Summary
Replaced 1Password CLI (`op run`) with macOS Keychain for runtime secret injection in launchd jobs. Eliminates dependency on 1Password desktop app on Mac Mini.

## Details
- Created `scripts/autopilot-env.sh`: wrapper script that reads secrets from macOS Keychain (service: `autopilot`), exports as env vars, then `exec`s the command
- Created `scripts/keychain-sync.sh`: utility for populating/updating/verifying Keychain entries (interactive, single-secret, and `--verify` modes)
- Updated both launchd plists to call `autopilot-env.sh` instead of `op run --env-file=.env.template`
- Fixed double `op run` bug in `com.merrittocratic.autopilot.post.plist`
- Removed `EnvironmentVariables` block from plists (now handled by wrapper)
- 12 secrets migrated to Keychain, all verified ✅
- Commits: `4690196`, `c069ada`, `6ab8420`

## Why
`op run` requires the 1Password desktop app running with CLI integration enabled. In launchd context, there's no interactive session to authenticate. Additionally, giving the Mac Mini access to the full 1Password account (including Personal vault) was an unnecessary security exposure. Keychain secrets are scoped to the `autopilot` service and encrypted at rest via the login keychain.

## Verification
- `./scripts/keychain-sync.sh --verify` — all 12 secrets confirmed ✅
- `./scripts/autopilot-env.sh /usr/bin/env` — all 14 env vars (12 secrets + REVIEW_SHEET_ID + R_LIBS_USER) injecting correctly
- Full `--check` run completed end-to-end: 10 articles processed, 48 tweets drafted and written to Google Sheets

## Rollback / Kill Switch
- Revert plists to previous versions (restore `op run` in ProgramArguments)
- Keychain entries can be deleted: `security delete-generic-password -s autopilot -a <KEY_NAME>`
- Previous plist versions in git history

## Follow-ups
- [ ] Note: `security unlock-keychain` required when SSH'd in before running `keychain-sync.sh`
